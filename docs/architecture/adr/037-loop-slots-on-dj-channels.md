# ADR 037: Loop slots on DJ channels (DJ-channel output of the arrangement)

Status: built on main (plan 2026-11-13 `dj-view-places`, slice 2, tasks 4 and 5: commits 8a67b0e0, 084abe96, 134aefcb). The server rules (module fader, `kanal_offen`) and the page follow in tasks 7 to 9; the measurements on the test instance are task 9. Andreas' listening acceptance is open.
Decided: by Cypher as defaults in the plan `docs/superpowers/plans/2026-11-13-dj-view-places.md` (decisions 5 to 9, spec section 6) and during the build (decisions 10 to 14 below); Andreas may override. Origin: Andreas, 2026-11-13 (DJ view with places, loop slots as real channels).
Supersedes: nothing. It adds an output kind; the production master and nested groups (ADR 036) work as before.
Predecessors: ADR 033 (routing, production master), ADR 036 (nested groups: a DJ output sits on a top group only).
Interface text: `docs/architecture/INTERFACES.md` section 4.11 (playback `live` and the group output `dj`) and section 20 (change log 2026-11-13).
Spec: `docs/superpowers/specs/2026-11-13-dj-view-places-design.md` section 6.

## Context

The live container holds two loop slots, A and B. A module placed there is a group of the arrangement, and until now every group played into the production master, which the kernel adds into `erz/4`. Both slots therefore shared one channel strip, and a slot could not be faded, filtered or cued like a deck. The DJ view wants every place to have the same kind of strip. A strip built from an EQ insert on the module group would avoid a core change, but it gives a -24 dB "kill", no DJ filter and a strip that behaves differently from all others. `pad/1` and `pad/2` are full DJ channels already (trim, EQ, kill, filter, fader, PFL) and shown in the mixer; the core loop boxes that used them leave the page and the hand tools in slice 3.

So the arrangement needs a third kind of output next to master and group: a DJ channel, whose input is added in front of the strip of `pad/1` or `pad/2`.

## Decision

1. **New output kind `dj`.** A top-level group of a live project may have `ausgang = {art: "dj", nr: 1|2}`: slot A leads into `pad/1`, slot B into `pad/2`. The playback snapshot head carries `live: true` only for a live project. The loader refuses `art: "dj"` without `live`, with `nr` outside 1 to 2, and on two groups with the same `nr` (reason `format`). A nested group has `gruppe` as its output, so a DJ output is structurally a top group; a track keeps master or group. Reason: the spec allows it only for the live container; a production project keeps `erz/4` and its bytes.
2. **Derived, not stored.** The project file is unchanged. `djk/ui/project/playback.ts` sets the output of the top group whose `modul.slot` is `A` (nr 1) or `B` (nr 2) when the project has `live: true`. A module in a production project has no `slot` and routes to the master as before. Reason: the output cannot drift out of step with the slot.
3. **Real-time exit.** `Arrangement::block` keeps its signature. Two stereo pairs arrive through the setter `dj_ausgang()` (index 0 = `pad/1`, 1 = `pad/2`; like `dj_schluessel`: pointer stores, good for one block, cleared at its end), and a group with a DJ output adds there instead of into the production master. The kernel (`core_signalbox.cpp`) zeroes and hands a pair only when a group of the snapshot leads into that channel (`dj_kanal_aktiv`), and adds it into the channel input (`erz_l_`/`erz_r_` of `pad/N`) after the loop boxes and the streams and before the recorder tap and the strip. The pairs are members of the kernel sized at construction: no allocation, lock or loop of unbounded length in the callback.
4. **Production master tap.** `pm_abgriff_*` carries what still goes to the master and therefore not the module. A DJ group does not enter the production master sum.
5. **Offline treats a DJ output as master.** `Arrangement::setze_dj_als_master()` (called by `cypherdj-render` before block 0 and by nothing else, `Kern::setze_arr_dj_als_master`) routes DJ groups into the master sum and so into the production master tap. Export, loudness, merge, bounce and the level offset of `areas/live/level.ts` see the module, and "render live equals production" stays bit-identical for everything that runs through `cypherdj-render`. The spec also lists freeze and stems: freeze is the live core in front of the fader and stems is the GPU separation, and neither renders offline through this program.
6. **Recording and envelope.** The recorder tap and the envelope ring of `pad/1` and `pad/2` see the module after the strip's input stage, so a module can be recorded back into the loop library (spec 6.5, accepted). Other sources on `pad/1..2` (Strudel streams 9 and 10, the core loop boxes) add into the same input and are not offered by the page.
7. **The module group fader is 0 dB from now on** (decision 9 of the plan: `baueModul` and `setzeModulEin` stop writing -200; the channel fader is the only gain). This is the server part, built in task 7; the existing live projects at -200 are raised on open only when `pad/N` is closed.

Decisions taken while building:

8. **A DJ output is a pointer to a pair, and a missing pair means the master.** Without a pair for the channel (a caller that never called `dj_ausgang`, or the offline switch) the group adds into the production master, as before this ADR. Reason: a module that is audible on the master is a fault the hand hears; a module that vanishes is not. Cost: a kernel that forgets the call plays the module on the master.
9. **The DJ output does not run through the PM chain.** The pair is not the production master: no PM chain, no PM fader, no `PDC_PM_GRP` delay place and no side sum of the PM place. Reason: a module carries no sends and no inserts (`module_storage.ts:141-147` refuses them when a module is placed), so there is nothing to compensate; the group's own chain, if it had one, still runs in the group. A module from a project with PM latency is therefore not delayed to line up with the production master. It is the only path in the arrangement that skips the PM compensation, and it is on purpose.
10. **Hold after a swap (`dj_rest_`).** A swap that takes the DJ output from a group (`modul_leeren` removes the group; the group leaves the snapshot) keeps the channel for `DJ_REST` = 960 samples. The 96-sample fade of the group's tracks then runs into the DJ pair instead of the master. The first version counted the 960 samples down at the start of `mischen()`, before the group pass read them, and the kernel asked `dj_kanal_aktiv` again after `block()`: with a block of 960 samples or more (quantum 1024) the tail missed the pair and reached the master as a click. The countdown now runs after the pass in `block()`, and the kernel keeps the answer it had before `block()` for the add into the channel input (commit 134aefcb; kernel test at quantum 256, 512 and 1024 with `pad/1` at -12 dB).
11. **A group that changes from nested to DJ blends into the pair.** The old target of a target blend (`gziel_alt_`) of a DJ group is the pair too, so the tail from the master does not reach it.
12. **Head field `live` only in the `/2` file.** The page server writes `live: true` in `cypherdj-arr/2`; a live project always has groups (the module group) and so always writes `/2`. A live project without groups writes `/1` without `live` as before. The loader reads `live` as a boolean (anything else is `format`) and needs it for `dj`; it ignores the flag otherwise. A project without the `live` flag is written byte for byte as before: no new field, flat golden `flach_golden.json` and `kGolden` unchanged.
13. **Nested DJ output is not representable, not refused.** The loader reads the output of a group as one value (`master`, `gruppe` or `dj`). A group in a group has `gruppe`; there is no field that could say both. The loader does not need a separate check, and the translator derives `dj` only for a top group.
14. **Mutation targets.** `CYPHERDJ_MUTATION_ARR_DJ_OHNE_LIVE` (flag not required), `_OFFLINE_AUS` (offline switch ignored), `_INS_MASTER` (the DJ group also in the production master) and `_NACH_STRIP` (module added behind the strip) each make a test red; they are named in the CMake test list next to `test_arr_lader`, `test_arr_dj_kanal` and `test_render_dj_kanal`.

## Consequences

- **Formats.** Playback `cypherdj-arr/2`: optional head field `live` (bool) and the group `ausgang` kind `dj` with `nr` 1 to 2. No new OSC address, no new reason (`format`), version stays 1. An older core that does not know `dj` refuses such a playback with `format` (`ausgang.art ... unbekannt`): core and render program are built and started together, as with ADR 036. The project file is unchanged.
- **Agent texts and tools.** None in this slice. The refusal `kanal_offen` and the slot arguments come in tasks 7 and 11.
- **Cost.** Two float pairs of `MAX_BLOCK` in the kernel and two pointer pairs in the arrangement. The kernel zeroes and adds a pair only when a group leads into the channel, so the other channels and a production project run the same instructions as before. The cost run with a module on each channel is task 9.
- **Listening.** The level and the character of a module through the strip (EQ, kill, filter, fader) are Andreas' to judge in the acceptance listening.
- **Open.** The measurements of task 9 (slot A bit-identical on `pad/1` while slot B is exported, edited and cleared; no leak between the channels; no click when a slot starts or is cleared; `cb_max` within 1431 us) are not in this ADR. The leak of a stem group after `modul_leeren` is measured there too.

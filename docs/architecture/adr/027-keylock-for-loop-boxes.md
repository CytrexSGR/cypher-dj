# ADR 027: Keylock for loop boxes (variant rendered in advance, R3 offline in the network process)

Status: **superseded by ADR 029 (keylock in real time) for decisions 1 to 3 and 5**; 4 (direct path at 128) and 6 (REC conversion offline) remain in force (2026-10-08, task 7 of the plan `2026-10-06-keylock-echtzeit.md`: the loop box now stretches live with the Dehner, the variant render removed). Before that: implemented in branch `keylock` (slices 0 to 5), not merged; listening test was pending (2026-09-30, Cypher).
Trigger: ADR 026 let loops run along in varispeed, and the pitch drifts as a result (requirement A10, "Keylock is mandatory for everything", remained open). Andreas: "we need a master tempo that everything subordinates itself to".

Plan: `~/messungen/2026-09-30-keylock-plan/plan.md`. Reports per slice: `~/messungen/2026-09-30-keylock-umsetzung/` (`slice-01.md` to `slice-05.md`, review `slice-3b4-review.md`, closing `slice-3c.md`). Status and measured values: `docs/architecture/stand/tempo-folgen.md`, section "Keylock".

## Context

At a tempo ≠ 128 BPM the loop box reads its file with the step `bpm`/128 (ADR 026). The pitch follows the tempo: the varispeed capture of a loop at 135 BPM lies +92.07 ct away from the original (`slice-01.md`, table "Messwerte", MEASURED, n = 1). A REC at ≠ 128 resampled the capture with `umtasten` onto the 128 grid and wrote the same shift into the file (−92.17 ct in the file at 135 BPM, `slice-05.md` measurement 5, MEASURED).

## Decision

1. **One variant per box, rendered in advance, at resting tempo.** If the tempo holds steady for 250 ms at a value ≠ 128 (60 to 200 BPM), the network process renders the loop offline with librubberband R3 to the length `llround(F · 128 / bpm)` at unchanged pitch (`loop_stretch.cpp`, `rendere_keylock`; loop laid down three times, middle taken, so that the seam closes; R3 fed in 1024-frame pieces, `slice-03b.md` F1). Source of the thresholds: `slice-03.md` line 9.
2. **Render thread with lowest priority.** One thread in the network process (nice 19 and SCHED_IDLE), one render at a time, per box only the newest job (`keylock_render.cpp`). The target of an announced ramp (`/k/tempo/rampe`) is rendered in advance without 250 ms of rest; for that the box keeps two variants, of three the one farthest from the current tempo is dropped (Glanz 2.6, F12). The network holds per box three disjoint sets of fixed size (`netz.h` `KlBox`): held (variants at the core, until LOOP_ALT; emptied when the core loses events, `Ereignis::verloren` in /uhr), in transit (render jobs), failed (until the next fixed tempo or loop). One rule in one place (`kl_soll`): first the fixed current tempo, then the target; nothing while a wanted one is in transit; otherwise the first one that is neither held nor failed. Every job is announced to the core (`LOOP_ERWARTET`); a start at this tempo waits up to `START_HALTE_TAKTE` bars for the variant (Glanz 2.6, F14). REC jobs go before variants (decision slice 4, `slice-04.md`: someone is waiting for REC, a variant is an extra). The core gets no new thread.
3. **The core plays the variant with the existing Catmull-Rom path** (`spiele_frei`, position as before from the beat, step ≈ 1 instead of `bpm`/128). Per block it reads the version with the smallest pitch error |ln(`bpm`/T_r)|, also in ramps (Glanz 2.6, F12, `loopbox.cpp` `waehle_pfad`), and crossfades in 20 ms beforehand (path change since Glanz 2.6 via `LOOPBOX_PFAD_BLENDE` = 4800 frames, 100 ms, heard on 06.10.: "neu4800 is smoother, but otherwise I don't really notice any difference"; loading into a sounding box still `LOOPBOX_LADEN_BLENDE` = 960) (`slice-02.md`, `plan.md` line 37). It rejects a variant with another name or another beat count.
4. **The direct path at exactly 128 BPM has priority and remains unchanged**: no render, no variant, bit-identical. Measured against the running core: 0 of 815 040 frames different against the comparison binary without keylock, zero `keylock:` lines in the journal (`slice-05.md` measurement 3b, MEASURED). The box output, the capture buffer and `rec/loop.f32` are also `cmp`-identical in the source comparison deed561 against 2ba183e (`slice-3b4-review.md`, "Held").
5. **If the variant fails** (render error, thread cannot be started, tempo meanwhile a different one, loop swapped), the box plays as before in varispeed. The exception appears in a stderr line; nothing leaves the thread (`slice-03b.md` F5).
6. **REC at T ≠ 128 keeps the pitch.** The capture (N beats at the tempo of the recording) goes to the same thread and is brought to N · 22 500 frames with R3 (time ratio, pitch 1.0, range 60 to 200 BPM); only then does the network write the file and send `/e/mitschnitt`. At 128 the synchronous path without R3 remains. `umtasten` is out of `schreibe_loop` and is called only by its own test (`slice-04.md`, concerns 4). Measured: file −0.00 ct, playback at 135 BPM with keylock −0.01 ct, failure case old binary −92.17 ct (`slice-05.md` measurement 5).

## Discarded

| Route | Why not | Source |
|---|---|---|
| Phase vocoder or WSOLA as own build in the core | There is no FFT in the core (`grep` over `src/`, `include/`, `dsp/`: 0 hits). FFT, phase tracking and transient handling would have to be built anew, and the pitch-scan measurement (M19) would have to be repeated for the own build. R3 already has it (G1 ±0.2 ct); R2, SoundTouch and Signalsmith failed in the workbench. WSOLA shifts content by the search tolerance against the beat position (on this, the plan says: GUESSED, unmeasured) | `plan.md` line 16, ADR 006 |
| Rubber Band live in the box | Later, not now. The position is then determined by the stretcher, not by the beat (external measurement WASM path 0.18 ms, about 9 frames, the box tests demand ±3 frames; phase control needed). Ramp pitch measured natively only as timing. Own costs: R3-fine in the 256-frame block mean 296 µs, p99.9 457 µs, maximum 4458 µs against a 5333 µs budget, two boxes, start delay 2048 frames. Roadmap size L (slices 34, 50 to 52). The advantage would remain: the only way that holds the pitch in ramps | `plan.md` line 17 |
| Store loops at the tempo of their recording | see ADR 026 | ADR 026 |
| REC at ≠ 128 still with resampling (`umtasten`) | changes the pitch by 12 · log2(T/128) semitones, cancels only with the box's varispeed, and would stay out of tune with keylock (−92 ct at 135 BPM) | `slice-04.md`, `slice-05.md` measurement 5 |
